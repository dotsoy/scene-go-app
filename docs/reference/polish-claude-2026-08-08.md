## 屏 01 — IDLE 待机·触发入口

### 一屏语义

**核心意图**: 用户打开 App 的起点,唯一目标是用最低摩擦发起一次表达(语音为主,文字/拍照为辅)。这页决定了产品的第一印象和核心价值主张的感知。

**当前已知元素**(根据 SCN-05/08/09/11e/13f/SCN-16b):
| 元素 | SCN 引用 | 状态 |
|------|---------|------|
| StatusBar | 基础 | 常驻 |
| LocSub 语言行「普通话 → 泰语」 | SCN-13f / SCN-16b | ✅ |
| HoldMic 中央大按钮(长按说话) | SCM-15a心智 / SCN-21 未提及但隐含 | ✅ |
| InputBar 底部输入区 `输入你想说的话…` | SCN-05 / SCN-16b | ✅ |
| InputBar CamBtn(拍照) | SCN-09 / SCN-16b | ✅ |
| InputBar MicBtn 禁用 | SCN-08 / SCN-16b | ✅ |
| BrandRow 右上角「更多」齿轮(→13) | SCN-19c | ✅ |
| SafetyFAB 右下角悬浮 | SCN-11c / SCN-14c / SCN-16c | ✅ |
| ❌ OfflinePill / OffChips | SCN-11e / SCN-16b | 已删除 ✅ |
| ❌ TriggerRow | SCN-09 / SCN-16b | 已删除 ✅ |
| ❌ InputBar 默认 MicBtn | SCN-08 / SCN-16b | 已禁用 ✅ |

### 保留清单

| 元素 | 理由 |
|------|------|
| **LocSub 语言行「普通话 → 泰语 ›」** | 告知当前位置和目标语言,是 06 国家选择模态的触发入口;同时提供目的地切换预览(SCN-11d)的前置路径 |
| **HoldMic 中央大按钮** | 产品 P0 核心交互;长按说话→松开成卡→全屏展示,零学习成本 |
| **InputBar 底部输入条(CamBtn + Field)** | 文字兜底(P1 输入渠道) + 拍照成卡(P1 输入渠道);职责单一,与 HoldMic 分工明确 |
| **「更多」齿轮(右上,→13)** | 低频次设置可达性;静音视觉存在,不打扰主路径 |
| **SafetyFAB(右下)** | P0 全局安全入口,任何页面 2 秒可达;紧急场景独立于主流程 |

### 精简或重构建议

| # | 操作 | 原因 |
|---|------|------|
| S1 | **合并 LocSub + 位置行为一行「来源标注行」** | 当前如果 LocSub 上方还有 GPS/定位状态行(handoff §4 提到"GpsBadge 'GPS'→'定位'"在 06 屏,但如果 01 也有类似元素则冗余)。将"定位来源"(GPS/手动)与"语言对"合并在同一行:「📍 泰国 · 曼谷 · 普通话 → 泰语 ›」。减少两行→一行,释放垂直空间给 HoldMic。如果 01 目前只有一个语言行(LocSub)且没有单独的定位行,则此条为 NOOP — 但在 06 模态拆分职责(cmd 审阅 CM-1 P0)时需注意:语言行不应承担双重角色,01 的行应侧重"我到了哪里",选中国家后才侧重"语言切换"。 |
| S2 | **HoldMic 添加明确的按压态视觉反馈** | SCN-08 禁用了 InputBar MicBtn 因为"中央大 HoldMic 已定义按住说话心智",但 hold-to-speak 必须有 **按压时的视觉变化**(波形动画/缩小旋转/背景高亮)。纯静态的大圆按钮容易被忽略。建议:按下→按钮缩小 10% + 声波扩散动画 + 数字倒计时显示(≤3s 直接出卡,>3s 显示持续录音中);松开→按钮回弹至原始大小。这是红线"操作必有反馈"的直接要求。 |
| S3 | **CamBtn 需明确导航连接** | SCN-09 定义了 InputBar 保留 CamBtn,但 `transition-spec.md` G5 标记为缺口(有 UI 无导航)。如果本期不实现 01→04 Push,至少应在 CamBtn 上加 **按住态**(长按 0.3s 进入取景器而非单击),以避免与普通点按混淆并强化"拍照"心智。 |

### 重点突出建议

| 策略 | 说明 |
|------|------|
| **HoldMic 占屏 30-40% 高度** | 这是用户打开此页应该做的第一件事。占据最大视觉权重,居中放置,周围大量留白。不要让它被其他元素挤压到屏幕下半部。 |
| **InputBar 贴底但不抢眼** | 使用低对比度描边($text-muted 边框)而非实心背景,使其退居视觉层级第二位。文案 $text-muted 级别(非纯黑)。 |
| **语言行弱存在感** | 小号字($text-muted),靠上但不居中,不影响 HoldMic 的中心地位。 |
| **齿轮/FAB 极简存在** | 两个入口都应是最小图标尺寸,不争夺注意力。 |

### 交互闭环缺口

| # | 缺口 | 严重度 | 说明 |
|---|------|--------|------|
| N1 | **HoldMic 长按 → 生成中 → 全屏 → 返回 01 的全链路未完成** | 🔴 P0(G4) | `transition-spec.md` G4 指出:SCN-15a 定义了"长按说话→松开成卡→全屏大字"的心智,但没有具体的成卡加载态(Skeleton"翻译中…"→"稍等正在思考")。用户在 01 按下松开后如果没有视觉反馈,不知道发生了什么。需要:①HoldMic 按下态(声波);②松开后生成中态(Skeleton + 文字);③全屏大字 03 的淡入过渡;④点全屏任意处退出回到 01。 |
| N2 | **01 的错误态未定义** | 🟡 P1 | 如果语音识别失败(无输入/环境噪音大)、AI 模型不可达、或网络完全断开,01 应该如何反馈?产品红线说"操作必有反馈",但目前只定义了成功流。建议在 InputBar 附近加一个临时 Toast 区域用于错误提示(3s 自动消失,不影响布局)。 |
| N3 | **从 06 确认国家后如何回到 01** | 🟢 P2 | Modal 关闭后应精确回到 01 原位置。目前 SCN-13f/17b 改了 06 的元素但没有记录 01→06→01 的回退动效细节。 |

### 本屏一句话结论

> **01 是整张脸的鼻梁——它必须直**。HoldMic 是当前唯一的明星,其余所有元素都应为它让路;当前的清理(SCN-08/09/11e)做得很好,下一步是把 HoldMic 的按压态和成卡管线(G4)补齐,让这张脸活过来。

## 屏 02 — 表达卡·成卡结果

### 一屏语义

**核心意图**: 用户表达后收到的结果展示页。这里不是"浏览一堆可能的选项",而是"确认我的表达是否正确,以及如何继续对话"。当前结构经历了多次迭代(6 卡→3 卡→双气泡),最终形态应是**聊天式会话界面**——一方说、一方听、可接话。

| └ 泰语大字(กรุณาคิดค่าโดยสารตามมิเตอร์) | SCN-22 | ✅ |

| **SafetyLink** | 低打扰的安全提醒,放在对话下方合理;点击进 08 SafetyDrawer。 |
| **ExprCard 组件级保留** | 作为通用表达卡组件未来可能在其他地方复用(如 10 安全信息页),保持为 reusable 无害。 |

## 屏 03 — 全屏大字展示

### 一屏语义

**核心意图**: 把表达式卡的最大字号、最高对比度呈现给对面的人看。这是用户举手机递出去的动作——**一切为"清晰可读"服务,没有任何多余的元素**。

### 当前已知元素(根据 product-claude.md §1 + SCN-15a 心智):

| 元素 | SCN 引用 | 状态 |
|------|---------|------|
| 全屏大字外语文本 | product-claude.md §1 | ✅ 核心 |
| 中文释义(可选展示?) | product-claude.md §1 省略预览 | ⚠️ 待定 |
| 加载骨架屏 "翻译中…" → "稍等,正在思考" | product-claude.md §1 | ⚠️ 待定(G4 缺口) |
| 退出方式:点按任意处返回上一屏 | product-claude.md §1 | ✅ 心智定义 |
| 动画:"卡片放大"(morph from card position) | product-claude.md §1 | ⚠️ 待定 |

### 保留清单

| 元素 | 理由 |
|------|------|
| **大号外语正文** | 这是 03 存在的唯一理由。字号应尽可能大(参考: 屏宽 -32px 的内边距下,单行能放下多少字,超出换行)。建议使用系统字体 maxFontSizeMultiplier 保证可读性。 |
| **加载骨架态(Skeleton)** | 从松开 HoldMic 到成卡显示的 2 秒空白期是信任崩塌的高发期。Skeleton "翻译中…" → 延迟后变"稍等,正在思考"缓解等待焦虑(product-claude.md §1 P0)。 |
| **退出:点按全屏** | 极简的退出机制。一次点击即可回到表达卡 02。 |
| **全黑背景 + 白色/高对比文本** | 纯黑极简原则;对面的人看得清是关键,所以外语正文可能需要 $text-primary(近白)甚至 accent-yellow 特殊高亮(如果是紧急句)。 |

### 精简或重构建议

| # | 操作 | 原因 |
|---|------|------|
| M1 | **严格禁止任何多余元素** | 03 是"递给别人看的卡片",不是你的交互测试台。不能有:返回按钮(点任意处退出)、音量调节、分享按钮、设置齿轮、SafetyFAB(已定义不加,SCN-12f)、任何导航箭头、任何标签。**只保留:文本 + 可选的中文副行(如果用户想对照看)**。 |
| M2 | **中文释义只在 03 屏以极低优先级展示** | 产品报告决定"省略预览、直接全屏",但用户递出卡片的同时自己也想确认说的是否正确。建议:在大字外语下方以 $text-muted 显示中文释义(字号减至外语的 50%,居中),作为用户的私人参照,不影响对面人看到的清晰度。 |
| M3 | **删除 03 上的 SafetyFAB 实例** | SCN-12f 已明确"03 沉浸屏不加 SafetyFAB"。但需确认画布上没有误插。 |

### 重点突出建议

| 策略 | 说明 |
|------|------|
| **文本撑满屏宽的 80-90%** | 最大化可读性。超长句子分多行,每行不宜超过 20 个字(泰语字符较紧凑,可适当放宽)。 |
| **加载中:中心旋转环 + "翻译中…"** | 简洁的 skeleton,不要花哨的粒子效果。纯黑底 + 白色旋转环(半径约 40px) + 16px "翻译中…" ($text-muted)。 |
| **出卡动画:从 HoldMic 中心放大** | 卡片从屏幕中央 HoldMic 的位置开始,morph 至全屏(250ms ease-out)。这个空间连续性让用户理解"刚才按的那个东西出来了"。 |
| **退出动画:缩小回原位置** | 反向 morph(200ms ease-in),给用户"卡片收回去"的体感。 |

### 交互闭环缺口

| # | 缺口 | 严重度 | 说明 |
|---|------|--------|------|
| N10 | **01 → 03 完整管线(加载态 + 成卡 + 返回)** | 🔴 P0(G4) | 这是整个产品的 first value moment。缺少 Skeleton 态意味着用户松开 HoldMic 后有 2 秒的未知期,可能以为 App 死了而反复按压。必须在 SCN-23 补全这一链路。 |
| N11 | **03 → 02 返回的目标** | 🟡 P1 | 点按退出后回到 02 还是 01 ?逻辑上应回到 02(表达卡),用户可以从那里选择"换一句"或"继续对话"。直接回 01 等于丢弃了整个对话上下文。 |
| N12 | **03 的网络异常态** | 🟢 P2 | 如果 AI 模型不可达,生成失败,用户看到了什么?建议:全屏红色边框提示("网络不可用,显示预设表达") + 下方「使用预设:你好/谢谢/再见」三个备选按钮。不阻断用户体验。 |

### 本屏一句话结论

> **03 是产品承诺的物理化身——它应该是你见过的最简单的屏之一,简单到几乎像是个 bug**。当前最大的缺口是加载态管线(G4),一旦补齐,Skeleton→成卡的过渡就是用户感受到"这个 app 真的有用"的第一秒。

## 屏 04 — 内联相机

### 一屏语义

**核心意图**: 拍照 → 交给 VLM/OcrPlugin 识别 → 生成表达卡。**用户此刻的全部注意力都在取景器和即将拍下的照片上,任何分散注意力的元素都是干扰**。

### 当前已知元素(根据 SCN-09 的 CamBtn 定义 + 产品架构 + handoff 备注"元素杂乱"):

| 元素 | SCN 引用 | 状态 |
|------|---------|------|
| 取景器画面(VCAM Feed) | 核心功能 | ✅ 必需 |
| 快门按钮 | 核心功能 | ✅ 必需 |
| 引导提示/叠加层 | 产品需求 | ⚠️ 待评估(可能是杂乱来源) |
| 返回 BackBtn | 见 05→04 Push 返回 | ⚠️ 在 04 本身是否有返回?仅在 05 有 BackBtn |
| RetakeBtn(重拍) | 拍摄完成后 | ⚠️ 属于完成态,非取景态 |
| SwitchCamera 翻转 | 前置/后置切换 | ⚠️ 可能存在 |
| Flash/Torch 开关 | 补光灯 | ⚠️ 可能存在 |
| SafetyFAB | SCN-12f 定义 04 不加 | ✅ 应无(SCN-12f) |

### 保留清单

| 元素 | 理由 |
|------|------|
| **取景器画面(全屏背景)** | 用户来这里的目的就是看到眼前的世界并拍下。取景器应该占满整个屏幕,不留边距,不做装饰。 |
| **底部中央快门按钮** | 唯一的核心操作控件。圆形,直径 ~72px,半透明黑色背景 + 白色外圈,不遮挡取景器主体。 |
| **顶部的极简约束指示条(如果有)** | 例如"对准要拍摄的物体"——如果使用,应极简:12px $text-muted 居中,位于取景区域内但不靠近边缘以免被手势冲突截断。 |

### 精简或重构建议

| # | 操作 | 原因 |
|---|------|------|
| C1 | **删除所有引导/装饰叠加层** | SCN-09 提到 InputBar 保留了 CamBtn,但未定义 04 本身的布局。如果 04 上有引导文字、取景框虚线、比例提示、对焦圆圈、美肤滤镜选择器等——全部删除。取景器本身就是最自然的引导,用户知道怎么拍照。 |
| C2 | **快门按钮移到最底,紧贴安全区** | 不要悬停在屏幕中间。贴在底部安全区内(距离底 ~32px),这样手指自然握住手机时下拇指就够得着。 |
| C3 | **如果存在 SwitchCamera/Flash/Torch——移到点击右上角隐藏菜单** | 这些不是每次拍摄都要用的功能。用一个小的三点菜单或齿轮图标放在右上角,展开后才是"切换前后镜头"/"开闪光灯"。常态下只显示快门和返回通道。 |
| C4 | **删除 RetakeBtn 在取景态的可见性** | RetakeBtn(重拍)只在**拍摄完成后的预览态**出现。取景时不应该看到"重拍"按钮。如果取景→预览是一个模态覆盖(拍完后浮层显示缩略图 + 确认/重拍),那是另一个状态,不属于取景态。 |
| C5 | **删除一切色彩元素** | 取景器上不应有任何彩色标记(红框对焦、蓝框人脸检测)。如果需要辅助,用半透明灰线/文字。纯黑极简。 |

### 重点突出建议

| 策略 | 说明 |
|------|------|
| **取景器 = 壁纸** | 全屏画面即界面。不加分割线、不加重叠容器边框、不做毛玻璃效果。 |
| **快门按钮是唯一锚点** | 它是整个画面中最重的视觉元素。半透明底 + 白色外圈 + 按下态缩小 5% + 震动反馈。 |
| **拍摄后:预览浮层(非新屏)** | 拍完不应跳到新页面查看缩略图。应该在当前取景器上方叠加一个底部浮层(占屏幕下部 40%),显示缩略图 + 「✓ 使用」/「🔄 重拍」。确认后走 VLM pipeline → 表达卡 02。 |
| **RetakeBtn 仅存在于预览浮层** | 不在取景态出现,减少认知负担。 |

### 交互闭环缺口

| # | 缺口 | 严重度 | 说明 |
|---|------|--------|------|
| N13 | **01→04 的导航连接** | 🔴 P0(G5) | `transition-spec.md` G5 明确标记:InputBar CamBtn 有 UI 但无导航行为。从 01 点击 CamBtn 到打开 04 相机的 Push 尚未建立。 |
| N14 | **VLM 结果→02 的推送链路** | 🔴 P0 | 拍摄→VLM 处理→结果显示在哪?如果 04 拍完确认后立即跳转到 02(表达卡),那需要一个 push 连接。当前 04→?? → 02 的链路是断裂的。 |
| N15 | **04 内的错误态(无摄像头权限/黑屏/闪烁)** | 🟡 P1 | 如果用户拒绝摄像头权限、或设备没有摄像头、或画面异常(黑屏),应该如何反馈?建议:全屏灰色占位区 + "请授予相机权限"文字 + 「前往设置」按钮。 |
| N16 | **04 是否应该有 BackBtn?** | 🟢 P2 | 如果 04 是通过 01 CamBtn 进入的(push),理论上应该能从 04 返回 01。但相机这种沉浸操作中取消是不常见的——用户要么拍了,要么放弃了。建议:右上角放一个小「×」关闭按钮(非 chevron-left 返回,因为返回的是"回到触发态"而非"后退一页")。 |

### 本屏一句话结论

> **04 是整张脸最需要动刀的地方——它目前很可能像一个"摄影 App 仿制品",塞满了取景框/对焦/滤镜/翻转/闪光灯的垃圾**。砍掉一切非快门元素,让取景器成为壁纸,快门成为唯一按钮,拍完用浮层预览而不是跳转新屏;这样 04 就从"杂乱的中间页"变成了"干脆的一拍即合"。
