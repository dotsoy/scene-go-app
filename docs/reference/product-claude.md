# SceneGo 产品层交互思考报告

基于产品核心承诺：秒级成卡、离线可用、精准表达。纯黑极简、无 emoji、禁技术术语、操作必反馈。

---

## 1. 主流程心智模型

**链路设计：3 步收敛为 2 步**

```
触发 → 表达式卡生成 → 全屏大字展示 → 完成
    ↘  （合并）  ↗
```

### 必须保留的步骤：
1. **触发**：用户明确的操作输入（语音/相机/文字）
2. **全屏大字**：表达式卡最终呈现形式
3. **完成**：表达式卡被对方理解

### 可以省略的步骤：
✅ **「成卡预览」省略**：直接进入全屏大字展示。理由：
- 出境用户注意力集中，额外的预览环节增加认知负荷
- 2 秒的生成时间不够长，预览变成「等待」的冗余
- 表达式卡本身已经是「成品」，全屏即是「最终交付」

### 设计决策（P0）：
- 卡片生成2秒超时，弹出骨架屏「翻译中…」，1秒刷新为「稍等，正在思考」
- 生成成功：直接平滑切入全屏大字，动画使用「卡片放大」的动效

## 2. 语音交互设计

**按住说话 vs 松开成卡 决策规则：**

| 使用场景 | 交互方式 | 逻辑 |
|----------|----------|------|
| **主动表达**（我方） | **按住说话** | 用户需要「中途可中止」的控制权：怀疑表达不准、想改词、怕误触敏感词 |
| **被动聆听**（对方回话） | **长按播放** | 用户需要「随时停止」的控制权：语言太快、想记笔记、需要翻页 |

### 设计决策（P0）：
- **表达卡生成**：语音输入 3 秒内停止按压，自动触发成卡；5 秒内可持续输入
- **播放对方回话**：长按播放按钮，松开即停止；播放期间亮起播放按钮作反馈
- **两种模式区分**：表达模式使用「麦克风+方框」图标，播放模式使用「耳机+波浪」图标

## 3. 紧急场景优先级

**「快」和「不误触」的平衡方案：**

### 触发机制：
- **双击护栏区域**：护栏位于屏幕左下角，双击激活「紧急模式」
- **护栏动画**：从屏幕底部弹出 3 个紧急卡片，背景色 #FF0000

### 卡片设计：
```
[保护] 我被抓了
[求助] 需要警察
[医疗] 我需要医院
[安全] 联系领事馆
[求爱] 我需要亲人
```

### 防误触设计：
- 卡片默认全屏不可滑动，只能「靠近底部」触发
- 执行操作前 3 秒「倒计时闪烁」，用户有机会取消
- 取消方式：**向上滑」或**「立即点击屏幕空白处」**

### 设计决策（P0）：
- 紧急卡片点击 500ms 延迟触发，视觉上「先亮红底区」再执行
- 每个卡片都携带「最近3次使用」标签，快速定位常用紧急表达

## 4. 空态与首次体验

**全新用户第一次打开 App：**

### 网络状态：
1. **有网络** → 展示「欢迎旅行」的滑块介绍 → 3 秒倒计时自动进入「触发」页
2. **无网络** → 展示「离线模式」的卡片 → 提示「首次使用需下载离线包」

### 无定位：
- 让用户手动选择「国家/地区」
- 搜索框「输入国名」或「选省份」
- 右上角「从地图选择」的备选方案

### 未下载离线包：
1. 显示「需要 12MB 离线数据包」的弹窗
2. 2 种选择：**「立即下载」**（WiFi 推荐） / **「稍后离线使用」**
3. 稍后离线：展示「文本输入」模式，语音/照片功能灰显

### 设计决策（P0）：
- 首次体验 3 步走：**「选择语言 → 了解功能 → 开始输入」**
- 离线模式下，默认使用「文字输入」+「已收藏的表达卡」+「最近浏览的物品」组合

## 5. 产品级交互矛盾或缺口

### 矛盾1：精准表达 vs 表达速度
- **矛盾**：用户希望「快速成卡」但又怕「表达式不够精准」
- **缺口**：没有「快速纠错」机制
- **解决**：
  - 全屏大字展示时，左下角添加「⚙️ 纠错」小按钮
  - 点击后弹出「替换词」的建议列表：「我想表达的是…」
  - **设计决策（P1）**：纠错弹窗右上角「接受更改」按钮，5 秒内有效

### 矛盾2：免费体验 vs 功能完整
- **矛盾**：免费用户可能会被「深度功能锁」吸引
- **缺口**：功能解锁提示过于突兀
- **解决**：
  - 将「深度场景」转化为「挑战」——「挑战 3 次成功表达」解锁下一关
  - 解锁成功后，弹出「恭喜，解锁『司机专属表达』」的庆祝动画

### 矛盾3：一致性 vs 场景适配
- **矛盾**：不同场景（机场/餐厅/医院）需要不同语言风格
- **缺口**：没有「情境模式」的切换入口
- **解决**：
  - 在「触发」页添加「情境」小标签栏：默认「通用」/「餐饮」/「购物」/「医疗」/「交通」
  - 选中情境后，表达卡底部显示「情境标签」+「该情境常用表达」
  - **设计决策（P2）**：情境标签灰度化，需要 3 次点击后自动弹出「情境快捷方式」浮层

### 矛盾4：完整性 vs 极简
- **矛盾**：用户需要「完整表达」但界面要求「极简」
- **缺口**：表达式卡信息量不足时，用户会担心表达不够清晰
- **解决**：
  - 在「表达式卡」底部添加「📋 详细版」的隐藏按钮
  - 点击后，从下方弹出「细节层」：
    - 本句中文释义
    - 常用近义词
    - 例句短语
  - 该层高度占满屏幕，滑动退出「细节层」即可返回表达式卡
  - **设计决策（P2）**：「详细版」按钮在无网络时灰显，提示「需要联网查看」

## 总结：核心设计决策优先级

| 决策 | 优先级 | 交付指标 |
|------|--------|----------|
| 主流程 3 步收敛为 2 步 | P0 | 表达式卡生成秒级完成，用户无需等待 |
| 语音按住 vs 松开机制 | P0 | 表达/播放模式按钮识别准确率 > 95% |
| 紧急场景 5 秒倒计时防误触 | P0 | 紧急模式误触率 < 1%，操作时间 < 8 秒 |
| 首次体验 3 步引导 | P0 | 首次触发者完成首卡率 > 85% |
| 纠错机制 5 秒免费纠错 | P1 | 纠错成功转化率 > 60% |
| 情境模式情境标签 | P2 | 餐饮类表达准确率提高 25% |

## 2026-08-08：Claude 审阅 — 主流程优先级 / 安全入口终态 / 结构性缺口 / 转场语义规范

> **背景**：App.tsx 当前为纯空占位视图（仅黑底），核心逻辑层完整可用（cardStackStore、speechController、sceneInference、plugins/…）。UI 于 2026-08-06 整体删除，待重建。本审阅从产品架构维度输出四项决策建议。

### A. 主流程优先级排序

现有五个能力路径，按「用户首次打开→产生第一次价值」的漏斗排列：

| # | 路径 | 心智模型 | 触发方式 | 是否刚需 | 建议优先级 | 理由 |
|---|------|----------|----------|----------|------------|------|
| 01 | **IDLE → 语音成卡** | "按下说话，秒出卡片" | 长按麦克风按钮 | ✅ 是 | **P0** | 这是产品的核心价值主张——秒级成卡，最低摩擦的触发方式；离线也可用（本地 VLM / 预设场景库）；零学习成本 |
| 02 | **表达卡生成 & 入栈** | "我的表达进入卡栈" | 01 自动后处理 | ✅ 是 | **P0** | 属于 01 的下游环节，不可分割；需配套 cardStackStore 与底部卡导航 |
| 03 | **全屏大字展示** | "递卡给当地人看" | 点击卡或自动生成 | ⚠️ 部分 | **P0/P1 合并** | 已在产品思考报告中决定省略预览、直接全屏；但与 02 本质是一个动作的两面，不应拆分为独立开发阶段 |
| 04 | **相机拍摄成卡** | "拍什么翻译什么" | 底部相机按钮 | ⚠️ 需要 | **P1** | 重要但不是首次体验必经之路；VLM/OcrPlugin 已有基础设施；需在 01 验证后再投入 UI 资源 |
| 05 | **图片解读(VLM)** | "看菜单/路牌/标志" | 从相册选图 + 相机 | ⚠️ 需要 | **P1** | 与 04 共享底层 pipeline（相机→压缩→VLM→结构化）；可合并到同一个 `CameraFlow` 页面中开发 |

**结论与建议：**

- **第一阶段（P0）只做一条路**：`IDLE 页 → 长按说话 → 识别 → 成卡 → 全屏大字自动展示`。不要并行做相机和图片解读。这条路的完成度决定了用户是否会留下来。
- **第二阶段（P1）扩展输入渠道**：在 IDLE 页底部增加相机按钮，共享同一条成卡 pipeline。相册导入作为 P1.5 锦上添花。
- **关键约束**：所有阶段都基于同一套 core 层（cardStackStore + expressionEngine + sceneInference），不会互相阻塞。但 UI 层面务必串行推进——先跑通一条路的全部闭环，再叠加第二个输入源。

### B. 安全入口最终形态：SafetyFAB + 抽屉

#### 设计假设检验

产品文档(product-cmd.md §4)已确定"紧急是低频高严重度，不该占 tab"。在此前提下：

- **SafetyFAB 悬浮按钮**放在任意页面右下角 — ✅ 合理。保证全局可达性（符合 2 秒规则），不占用任何一级 Tab 空间。
- **08 抽屉(SafetyDrawer)**从底部弹出 — ⚠️ 需明确边界。抽屉适合"L1 详情层"(电话、使馆列表)，但不适合 L0(当前最紧急的表达句)。L0 应该以**模态全幅覆盖**形式出现。

#### 推荐的最终形态

```
┌─────────────────────────────┐
│  ...app content...          │
│                             │
│                     [🛡]    │ ← SafetyFAB (右下, z-index: 999)
│                             │
└─────────────────────────────┘

点击 FAB → SafetyDrawer 从底部滑出(P0)：
┌─────────────────────────────┐
│ ┌─────────────────────────┐ │
│ │           ▲             │ │ ← 拖拽柄
│ │   紧急求助                │ │ ← L0: 意图级大按钮
│ │                         │ │
│ │  [遇到危险] [身体不适]    │ │ ← 双击护栏区域同样触发
│ │  [旅游纠纷] [联系使馆]    │ │
│ │                         │ │
│ │  ─── 展开 ───            │ │
│ │  📞 警察 191  📞 救护 1669│ │ ← L1: 号码详情层
│ │  🏢 使馆信息             │ │
│ │  ℹ️  防骗提示             │ │ ← L2: 次级折叠
│ └─────────────────────────┘ │
└─────────────────────────────┘
```

#### 还需补充的设计点

| 缺项 | 说明 | 优先级 |
|------|------|--------|
| **触发方式统一** | FAB 点击 + 左下角双击护栏区域 都能打开安全层。两种触发在心理上等价（都是"紧急信号"），但在物理位置上互补——FAB 在大屏拇指舒适区，护栏在小屏单手操作区 | P0 |
| **防误触确认** | 每个 L0 意图按钮长按 0.6s + 进度环 + 震动反馈，不需要二次弹窗（product-cmd.md 已定案） | P0 |
| **L0 vs L1 分离** | FAB 抽屉内顶部必须是 L0（意图级大按钮），不是号码列表。号码和使馆归入 L1 折叠区。当前问题是把 L0+L1 混在一起 | P0 |
| **事件路径引导** | 抽屉底部加"接下来做什么"三步指引（遇到问题→报警→补办证件→联系使馆），给慌张中的用户一个心理锚点 | P1 |
| **离线降级态** | 安全卡中的使馆地址、在线预警在无网时灰显并标注"需联网"。电话号码始终亮色（核心承诺不受离线影响） | P1 |
| **TabBar 隔离** | safety drawer 应在 z-index: 999 层级打开，覆盖 TabBar，避免用户关闭抽屉后发现自己在错误的 Tab 页上而困惑 | P0 |

### C. 结构性缺口：TabBar 三个空 Tab 需要什么页面

现状：TabBar 已从旧版改为三 tab（对话 / 笔记 / 更多），但 App.tsx 为空，没有任何页面挂载。这是一个**从 UI 架构倒推的功能需求清单**。

#### 必须优先设计的页面及 IA

以下是从零开始重建 UI 时的**页面清单**，按依赖顺序排列：

```
Phase 0 — 启动壳（已完成，无需新页面）
  App.tsx → <BlankBlackView />

Phase 1 — 第一条完整用户旅程（P0）
  ChatScreen          ← 对话 Tab 的主页面
    ├─ IdleState       ← 未触发时的待机态（核心！）
    │   ├─ 位置行（国家/手动选择入口）
    │   ├─ Tap&Talk 兜底卡入口
    │   └─ "长按说话" 主按钮
    ├─ RecordingState  ← 录音中视觉反馈
    │   └─ 声波动画 + 倒计时
    ├─ GeneratingState ← 成卡加载态
    │   └─ 骨架屏"翻译中…" → "稍等，正在思考"
    └─ CardFeed        ← 本次会话的表达卡时间线
        └─ 卡片列表 + 底部卡片导航条

  CameraFlow          ← 相机拍摄（P1，复用 Phase 1 框架）
    ├─ CameraCapture   ← 取景器
    └─ ImageResult     ← VLM 结果展示

Phase 2 — 回顾与管理（P1）
  NotesScreen         ← 笔记 Tab 页面
    ├─ NoteList        ← 收藏/星标表达卡片列表
    └─ NoteDetail      ← 单条笔记详览 + 编辑备注

  SettingsScreen      ← 更多 Tab 首页
    ├─ API Key 配置
    ├─ 目标语言设置
    ├─ 默认模型选择
    ├─ 目的地/国家管理
    ├─ 离线包状态（总览态，非逐个管理）
    └─ 应用信息 / 清除缓存

  SafetyDrawer        ← 全局覆盖抽屉（不属于任何 Tab）
    ├─ L0: 意图按钮组
    ├─ L1: 号码/使馆详情
    └─ L2: 防骗提示折叠区
```

#### 每页信息架构一句话摘要

| 页面 | 角色 | IA 核心结构 | 参考现有 |
|------|------|-------------|----------|
| **ChatScreen** | 主战场，承载全部交互 | idle → record → generate → cardfeed 四状态机 | SCREEN-01 ~ SCREEN-03 |
| **NotesScreen** | 回顾过去说过的话 | 列表 → 详情 | SCREEN-04 |
| **SettingsScreen** | 管理和配置 | 分组列表（密钥/模型/目的地/离线） | SCREEN-10 ~ SCREEN-13 |
| **SafetyDrawer** | 紧急兜底，全局覆盖 | 意图按钮(顶) → 号码列表(中) → 折叠提示(底) | SCREEN-07, SCREEN-08 |
| **CameraFlow** | 第二条输入管道 | 取景器 → 结果展示 | SCREEN-05, SCREEN-06 |

#### 实施顺序建议

```
第一步：ChatScreen — 实现 idle 态 + 录音 + 成卡展示（约 60% 工作量）
第二步：SafetyDrawer — 独立组件，随时可插入任何页面（10-15% 工作量）
第三步：NotesScreen + SettingsScreen — 从已有 store(NeoteStore, appSettings) 驱动渲染（15%）
第四步：CameraFlow — 复用 SceneGo 的 VLM plugin pipeline（10%）
```

> **关键洞察**：ChatScreen 的 `IdleState` 是整个应用的第一个可见界面。它必须包含：① 位置行（带来源标注）② 兜底 Tap&Talk 卡片 ③ 全局 FAB。这三样一旦到位，产品就"活"了。其余页面可以后续逐步填充 Tab。

### D. 转场语义规范建议

React Native / Expo 生态（推荐 React Navigation）的四种转场模式在本产品中的适用性：

| 转场类型 | 语义含义 | 本产品使用场景 | 动画建议 | 排除场景 |
|----------|----------|----------------|----------|----------|
| **推入(push)** | 层级下钻，有返回箭头 | 国家选择 → 国家详情；相机 → 图片解读结果 | 水平右进左退(horizonal slide) | 不应用于同级别切换 |
| **模态(modal)** | 全屏中断，焦点唯一 | 安全抽屉 L0 层、紧急表达的确认态、首次引导 | 自下而上升起(bottom-sheet modal) | 不应用于常规内容浏览 |
| **抽屉(drawer)** | 面板叠层，不丢失上下文 | SafetyDrawer(全局)、设置侧拉 | 从右侧滑入(right-drawer) 或从底部拉起(bottom-sheet) | 不适用于高频操作 |
| **堆栈替换(replace)** | 替换当前页面，无返回 | 首次引导结束 → 进入主页 | 淡入淡出(fade) | 谨慎使用，用户可能想回退 |

#### 额外规范

1. **同 Tab 切换**：对话 → 笔记 → 更多，永远用 **tab 切换**(水平滑动 + 惯性)，不做推入/模态/抽屉——它们在同一认知层级。

2. **跨级转场克制**：不允许从对话 Tab 直接推入到相机页面。相机应作为一个按钮出现在对话 Tab 的 Idle 态上，或者通过 FAB 触发（模态），而不是跳出当前 Tab 再导航回来。

3. **安全相关转场一律模态/抽屉**：不论从哪个 Tab 出发，安全功能都通过全局 FAB 弹出抽屉或使用模态覆盖，保持"紧急情况下的确定性行为"。

4. **手势可用性**：所有 push 转场必须支持右滑返回（iOS 惯例），所有 bottom-sheet 必须支持下拉关闭。没有例外。

5. **无障碍要求**：所有转场动画必须尊重 `Reduce Motion` 系统设置——检测到开启时，转为瞬切或最短淡入淡出。
