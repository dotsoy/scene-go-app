# SceneGo 产品层交互思考(安全信息 / 目的地切换 / 离线包 / 全局导航)

> 背景:SceneGo 是面向出境用户的语言沟通 App。用户拍照/语音/文字触发,App 识别场景并生成当地语言表达卡,让用户传达给当地人。核心承诺:**秒级成卡、离线可用、精准表达**。纯黑极简、无 emoji、禁技术术语、操作必反馈、紧急动作防误触。
> 本文件从产品全局视角,对安全信息、目的地切换、离线包、全局导航四个领域给出可执行的设计决策,并列出产品级交互矛盾与缺口。优先级:**P0 = 必须做,P1 = 应该做,P2 = 可选/后续**。

---

## 1. 安全信息体系:从「按机构」改「按意图」,2 秒规则决定分层

**核心判断**:紧张时用户想的是「我被偷了 / 我生病了」,不是「我要打旅游警察」。当前 07 屏把 191/1669/1155 三个号码并列,逼用户在 3 个选项里做选择——这本身就是 2 秒内做不完的事。

### 设计决策

- **按「求助意图」重排紧急号码(非按机构)**。三个大按钮的主文案改为场景词:
  - 「遇到危险」→ 191(警察)
  - 「身体不适」→ 1669(救护车)
  - 「旅游纠纷」→ 1155(旅游警察)
  - 用户匹配意图,号码是结果。数字仍大字展示(保持红线「直给」),但主文案是意图。(P0)

- **三级分层**:(P1)
  - **L0 常驻层** = 安全卡本身:求助句朗读 + 意图拨号。这是「现在要做的」。
  - **L1 详情层** = 08 底部抽屉:电话、使馆、求助句组。
  - **L2 主动层** = 本地提示、防诈骗:不与紧急内容同屏竞争注意力,在抽屉内折叠或次级入口。

- **补上「接下来做什么」**。当前体系只有「现在」,没有「之后」:被偷了 → 报警 → 补证件 → 联系使馆。建议抽屉内加轻量「事件路径」(如果遇到 X → 步骤 1/2/3),这是安全感闭环缺的那半环。(P1)

- **防误触定案**:全局统一「长按 0.6s + 进度环 + 震动确认」,不用二次确认弹窗——紧急时多一步都是负担。(P0)

## 2. 目的地/国家切换:定位只建议、绝不自动切;掌控感 = 预览 + 可见 + 可回退

**核心判断**:语言和紧急号码是「错的代价极高」的状态。自动切换的误判成本(边境漂移、漫游抖动)大于手动切换的麻烦成本。所以自动定位的角色是**提示器**,不是**执行者**。

### 设计决策

- **边界**:定位只在跨越「国家」时触发建议(城市内移动如曼谷→清迈不提示,安全卡与语言都是国家级);提示后 24h 内不重复;用户「保持」后,除非进入第三个国家否则不再自动提示。(P0)

- **切换前必须可预览**:用户看到「切换」前,先看到「切到日本后:语言对变为 普通话→日语、紧急号码 110/119、安全信息将基于日本」的预览卡——不预览就切,等于让用户盲签。(P0)

- **可回退**:不做「撤销」弹窗(用户可能 10 分钟后才想切回),改提供「最近国家」快捷列表(历史 3 国一键切回),位置行永远显示当前国家来源(定位 or 手动)。(P1)

- **手动入口永远可达**:首页位置行点击进 06;手动选择后位置行标注「手动选择:日本」,不再混入 GPS 状态,避免「定位说泰国、实际在日本」的信任崩塌。(P1)

## 3. 离线包策略:用户只该看到「能不能用」,不该看到「怎么实现的」

**核心判断**:26 国离线包的价值是「确定性承诺」,不是「存储管理任务」。版本号、MB 占用、26/26 数字都是技术细节,当前 10 屏整个是「工程师视角的体检页」。

### 设计决策

- **用户该看到的只有三件事**:(P0)
  - 「是否就绪」(当前所在国可离线使用);
  - 「首次准备中」的整体进度(一次性,后台下载全部 26 国,不给逐个管理的负担);
  - 空间不足时的清理提醒。

- **10 屏降级**:改为「离线状态」页,顶部是「覆盖 26 国 · 全部就绪」整体态 + 当前国就绪度;国家列表折叠、按需展开;删除入口藏到详情深处(用户一年做一次的决定,不该占一屏)。(P1)

- **删掉「检查更新」按钮**:更新走后台静默(按月自动),手动检查更新是技术心智。唯一需要打扰用户的场景:首次下载、空间不足、断网且目标国未下载(降级提示「该国家需联网,已尝试在线模式」)。(P1)

- **离线降级体验是最大信任缺口**:离线包是预设场景,AI 生成是自由的。离线时「识别场景生成卡」承诺会断——需要明确离线模式界面(场景库导航:交通/点餐/医疗/求助),并让预设库质量足够,让离线时 80% 日常场景仍可表达。(P0,详见第 5 点)

## 4. 全局导航:4 tab 是负担,推荐 3 tab——行动 / 回顾 / 管理

**核心判断**:「卡栈」与「对话」是同一个心智(「我说过的话」)的两个分身,用户分不清;而「更多」(设置)从不是高频功能,不配一级导航。这个 App 的使用模式 90% 是「当场触发 → 秒级成卡 → 展示给对方」,主行为是**触发**,不是浏览。

### 设计决策

- **推荐方案:3 tab = 主页(相机/语音触发)→ 对话(卡片流 + 对方回话)→ 我的(收藏 + 离线 + 设置)**。(P0)
  - **对话**合并「卡栈」与「对话」为一条时间线:每次触发产生的表达卡 + 对方回复,支持回放;
  - **笔记**并入「我的」作为「星标表达」子集,不单设 tab;
  - **离线状态页和设置**都从「我的」进。

- **TabBar 本身是否必要**:考虑到单手、当场、亮屏即用的定位,可以更进一步做「主页无 TabBar 的全屏触发 + 右上角进我的」。但保留 3 tab 给用户「我的东西有地方放」的安全感,折中推荐 3 tab。(P2)

- **Tab 里不放安全入口**:紧急是低频高严重度,不该占 tab;改成**全局悬浮安全入口**(任何页面右上角 shield 图标直达安全卡)。(P1)

## 5. 产品级交互矛盾与缺口(按严重度排序)

### P0(必须解决)

- **离线承诺 vs AI 生成能力的矛盾(最大缺口)**:离线包是静态内容,自由输入生成需要在线模型。当前 01 首页「26 国离线可用」徽章暗示了离线能力,但全设计没有「离线模式」界面。必须定义:离线 = 场景库导航,在线 = 自由生成,并在状态条明确「离线模式 · 26 国可用」,把降级从缺陷变成安心符。

- **安全入口藏得太深**:07 安全卡是内容流里的一个分类,紧急时用户要从对话流里找它。安全入口必须提升为全局常驻元素(悬浮入口 / 锁屏小组件),任何页面 2 秒可达。

### P1(应该解决)

- **安全信息的时效矛盾**:防诈骗预警是时效内容,静态离线包装不下,且会过期。决策:离线包只放「不变信息」(号码、使馆、电压、通用骗局模式),时效内容(今日骗局、突发事件)走在线推送,离线降级为通用提示。

- **「请对方说话」的转交体验缺失**:02 屏有「请对方说话 · 说完自动翻译」,但公共场所对陌生人举手机录音,对方会抗拒。需要「递给对方」的转交模式(对方语言的界面)和明确的监听中状态(仅按需监听、红点 + 倒计时),否则双向对话这半环立不住。

- **位置显示来源混用**:GPS 定位 vs 手动选择两种来源不区分,会因漂移产生信任崩塌。方案:位置行标注来源(「定位:泰国」/「手动:日本」),已在第 2 点给出。

### P2(可选/后续)

- **26 国质量一致性**:26 国内容质量不可能一致,用户到了小语种国家发现场景卡缩水,会觉得承诺缩水。决策:离线包按国家分级并在选择时明示(完整版/基础版),管理期望落差;或商业上保证 26 国同质。

## 优先级汇总

| 优先级 | 决策项 |
| --- | --- |
| **P0** | 紧急号码按意图重排;定位只建议不自动切;切换前必须预览;离线模式界面(场景库导航);全局常驻安全入口 |
| **P1** | 安全信息三级分层 + 事件路径;最近国家回退;10 屏降级为离线状态页;删掉「检查更新」;时效信息走在线推送;对方转交模式;位置来源标注 |
| **P2** | 无 TabBar 的全屏触发变体;26 国离线包按国家分级 |
