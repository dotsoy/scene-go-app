# Product Requirements Document (PRD) — SceneGo

> 更新：2026-08-03 —— 依据产品决策（**用户主动触发生成表达卡，不自动触发**），以当前代码实现为准。

## 1. 产品概述

SceneGo 面向**全球出境用户**：**用户主动触发**（拍照 / 语音 / 文字），App 识别当前场景并生成**符合该场景的当地语言表达卡**，让用户能立即把需求/情境有效地传达给当地人（司机、店员、警察、海关等）。

数据基础：10 类场景词库 + 26 国安全信息（版本化场景包，离线可用，可远程下发）。核心承诺：**秒级成卡、离线可用、精准表达**。

## 2. 核心功能规格

### 2.1 主动触发机制（用户主动，App 不自动触发）

- **CAM 双击拍照**：对准菜单 / 路牌 / 售票机拍照 → 提取信息 → 直接生成表达卡；卡面提供「AI 解读」多轮追问入口
- **MIC 双击语音**：说出需求（如"我要打车""我对花生过敏"）→ 生成当地语言表达卡；iOS 原生听写（Android 明确降级提示，引导拍照/文字）
- **Tap & Talk 文字表达**：一句话描述需求 → 生成当地语言表达卡
- **位置上下文（非触发）**：一次性前台定位（5 分钟缓存），用于国家匹配、安全卡与语言推断；不监听、不自动弹卡，权限拒绝不影响分析

### 2.2 表达卡系统

- **大字闪示卡**：当地语言大字 + 拉丁转写发音 + 本地惯例提示 + 一键 TTS 朗读，直接递给当地人看
- **双源生成**：离线词库匹配（本地快、免网络、成本零）与云端 VLM 动态生成（精准、可追问）互为兜底
- **安全卡**：按国家提供紧急电话（警察/急救/火警/旅游警察）、中国使领馆电话、求助句、骗局提示，一键拨打

### 2.3 本地工具

- 快速笔记（凭证/密码/退款号，一键复制、全屏大字）
- 会话历史（本地保存快照会话，可恢复追问）
- 表达卡 / 快照分享导出

### 3.1 关键实用度痛点与着重解决目标（重点攻克）

根据真实场景验证，当前单向表达卡模式在实用度上仍有突破空间，下一步版本将着重解决以下 4 个核心痛点：

1. **单向表达卡 ≠ 双向沟通闭环（无法应对对方回应）**
   - **痛点**：当前大字卡仅实现了“我出卡展示给对方”，一旦对方用当地语言回应（如出租车司机询问“前边加收 50 铢过路费可以吗？”），沟通链路瞬间中断。
   - **解决目标**：表达卡底部新增 **「听对方说话」** 快捷按钮，一键采集对方说话内容并瞬间翻译为中文引导（界面不出现技术术语），形成 **“我出卡 ➔ 对方回答 ➔ 我理解 ➔ 再次回应”** 的完整双向沟通闭环。

2. **菜单拍照孤立提取 ≠ 菜单决策助手**
   - **痛点**：拍一整页菜单仅提取单道菜品成卡，用户依然无法知晓整张菜单的招牌菜、忌口与过敏原，无法做出整体点餐决策。
   - **解决目标**：拍照后输出 **「菜单解读助手」** 面板（包含：招牌必点、过敏原/忌口预警、辣度标识），用户点击任意菜品再展开针对服务员的当地语言点餐卡。

3. **被动等待输入 ≠ 场景主动感知与推荐**
   - **痛点**：用户在机场、地铁站、深夜抵达等手忙脚乱的场景下，App 呈空白等待态，全靠用户手动打字或思考搜什么。
   - **解决目标**：结合 **GPS 位置 + 时间 + 国家环境** 自动感知当前场景上下文，主动在顶部推送场景建议胶囊（如机场场景推 `🚕 机场打车` `🚆 机场快线末班车` `📶 激活 eSIM`）。

4. **单句卡片表达有限 ≠ 复杂场景连贯步骤卡**
   - **痛点**：面对感冒药购药、退税申报、丢失护照等复杂场景，单张表达卡无法完成连续多步骤沟通。
   - **解决目标**：提供按步骤可翻页的 **「连贯步骤卡」**（如【药店购药指引】：第 1 步 表达症状 ➔ 第 2 步 表达过敏原 ➔ 第 3 步 询问用法用量）。

### 3.2 场景通用多阶段抽象 (ScenarioFlow) 与 界面设计禁忌

> ⚠️ **界面设计最高红线**：
> 1. **严禁在用户界面 (UI) 中出现任何技术/开发术语**：诸如 `SOP`、`VLM`、`Listen & Reply`、`Menu Hub`、`Done-Flag`、`Idempotency` 等词汇属于内部开发/模型术语，**绝不允许在界面与设计稿中暴露给用户**。界面文案必须 100% 采用自然、体贴、有温度的人性化中文（如 `药店购药指引`、`听对方说话`、`第 1 步 / 共 3 步`）。
> 2. **纯粹沟通定位（零支付/零交易）**：SceneGo **100% 专注于异国场景沟通与意图表达**，App 内部**不包含任何在线支付、订单结算或交易环节**。所谓“非幂等风险”仅指紧急呼叫警察/急救（191）或单次有效退税凭证展示，绝不涉及资金扣划。

#### A. 三阶段线型协商模型 (Linear Multi-Stage Negotiation Flow)
将药店购药、打车、退税、入住等复杂场景抽象为通用的 **需求 ➔ 约束 ➔ 确认** 三阶段结构：

1. **阶段 1：需求/状态陈述 (Demand Phase)** —— 表达核心需求（如“我发烧头痛”/“去机场”/“办理入住”）。
2. **阶段 2：约束/限制告知 (Constraint Phase)** —— 自动带入 Profile 个人档案（如“阿司匹林过敏”/“按表计费”/“禁烟房”）。
3. **阶段 3：交付/确认指引 (Confirmation Phase)** —— 询问后续动作（如“一天吃几次”/“车费多少”/“早餐时间”）。

数据模型 Schema (`ScenarioFlow`)：
```ts
export interface ScenarioFlow {
  flowId: string;           // 流程 ID (如 "flow-pharmacy")
  title: string;            // 场景标题 (如 "药店购药指引")
  totalSteps: number;
  steps: {
    stepIndex: number;
    phaseType: 'demand' | 'constraint' | 'confirmation';
    phaseLabel: string;
    cardData: CardData;
    nextActionText: string;
  }[];
}
```

#### B. 场景幂等性与安全分层 (Idempotency Architecture)
依据场景动作的侧副作用划分为两类，实现差异化防护（仅限沟通与安全）：

* **纯表达与展示类 (表达 / 询问 / 规则展示)**：
  * **特点**：无侧副作用，100% 离线预载，支持无限次安全重试与被动触发。
  * **代表场景**：表达忌口/过敏、询问按表计费、查 Wi-Fi 密码、小费规则展示。
* **高风险与紧急类 (紧急呼叫 / 单次凭证)**：
  * **特点**：涉及报警求助或单次凭证。
  * **防护规则**：挂载 `ActionGuard` 拦截器，增加已完成状态标记、二次确认弹窗，严禁自动重试。
